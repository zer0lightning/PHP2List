PHP2List / API and feeds

API and feeds

Use the list in your own scripts and tools.

In short

The same data the site shows is available as JSON, free and without a key, for scripts and security tools. It is unofficial: check important findings against the NCSC-NL source list and your vendors. There is no uptime guarantee and no support.

Endpoints

All endpoints are read-only (GET), need no authentication, and allow requests from any website (CORS Access-Control-Allow-Origin: *). Responses are JSON in UTF-8.

EndpointWhat it returns
/api/v1/softwareThe full software list: one item per product, with both CVE statuses, notes and links.
/api/v1/changesStatus changes in the last 30 days, newest first, each with the status before and after.
/api/v1/timelineCounts per status over time since disclosure (the data behind Patch progress).
/api/v1A short index of the endpoints above.
/feed.xmlAn Atom feed of the latest 50 status changes. Add ?v= once per watchlist entry to narrow it, for example /feed.xml?v=s%3ACisco&v=wordpress.

Example

curl -s https://php2list.com/api/v1/software | jq '.items[] | select(.s1 == "Vulnerable") | .id'

Fields: /api/v1/software

  • apiVersion: always 1 for this version.
  • listUpdated: NCSC-NL's "last status update" text, as published (not a machine-readable date).
  • fetchedAt: when PHP2List last fetched the list (ISO 8601, UTC).
  • sourceRevision: the NCSC-NL commit the data comes from, when known. official: false if it came from a mirror. sourceArchived: true once the source list is no longer updated.
  • count and items. Each item has:
    • id: a stable, URL-safe product ID such as cisco--cisco-meraki-dashboard. The product page is /#p=<id>.
    • supplier, product, version (the "Version (see Status)" column).
    • s1 and s2: status for CVE-2026-109618 and CVE-2026-109619: Vulnerable, Workaround, Investigation, Fix, Not vuln or empty.
    • notes (array of text) and links (array of {label, url}).

Fields: /api/v1/changes

  • days (30), generatedAt, count and events, newest first.
  • Each event has t (when the change was recorded, ISO 8601), id, supplier, product, version, the new s1/s2, prev (the statuses before, or null when the product was added), the first note and up to three links.

Fair use

  • Please cache. The data changes a few times a day at most. Checking every 15 to 30 minutes is plenty; responses can be cached for 5 minutes.
  • Abusive request rates may be blocked to keep the site available for everyone.
  • Stability: within v1, fields won't be removed or change meaning. New fields may be added, so ignore ones you don't know. The internal /api/software addresses used by the site itself may change without notice.
